# 카카오 채널·CRM SMS 중복 발송 방지 운영 프로세스

작성일: 2026-08-29

## 결론

카카오 채널 친구 약 7,700명과 CRM 회원 약 2,500명은 서로 다른 명단이다. 현재 CRM은 고객의 카카오 채널 친구 여부를 보유하지 않으므로, 단순 전화번호 필터만으로 두 채널 간 메시지 도달 중복을 완전히 제거할 수 없다. 따라서 카카오 채널은 **공개 이벤트 링크 유입**, CRM SMS는 **개인별 상태 안내와 미전환 고객 보완**으로 역할을 분리해야 한다.

## 발송 전 공통 원칙

모든 캠페인은 고유한 `campaignId`를 부여한다. 예: `sep_thanks_2026`. 같은 캠페인에서 동일 고객에게 같은 혜택을 두 번 주지 않는 것이 목표이며, 채널별 도달 수 자체를 0으로 만들 수는 없다. 카카오 메시지와 SMS에는 같은 캠페인 ID를 UTM 파라미터로 포함한 링크를 사용한다.

| 구분 | 카카오 채널 브랜드 메시지 | CRM SMS/LMS |
|---|---|---|
| 역할 | 이벤트 인지도·링크 유입 | 회원별 쿠폰·가입 상태·미전환 리마인드 |
| 대상 | 채널 친구, `I` 타게팅 | 활성 + SMS 마케팅 동의 + SOLAPI 수신거부 제외 |
| 혜택 전달 | 링크에서 본인 인증 후 조건 확인 | 개인별 쿠폰 코드 또는 동일 인증 링크 |
| 발송 시간 | 08:00~20:50 KST | 광고성 메시지는 08:00~20:50 KST |
| 금지 | CRM 개인 쿠폰 코드를 채널 전체에 공통 노출 | 카카오 유입·쿠폰 수령 완료자에게 동일 캠페인 재발송 |

## 권장 발송 순서

### 1. 카카오 채널 1차 발송

오전 10:00 KST에 채널 친구에게 이벤트 페이지 링크를 보낸다. 메시지는 혜택 개요와 링크만 포함하고, 개인별 쿠폰 코드나 CRM 회원 여부를 노출하지 않는다. 링크에는 `utm_source=kakao`, `utm_campaign={campaignId}`를 포함한다.

### 2. 링크에서 CRM 식별과 혜택 조건 판정

고객이 링크를 열면 전화번호 또는 이메일 OTP로 본인 확인을 한다. 인증 뒤 시스템은 회원 상태, 캠페인 쿠폰 기발급 여부, 해당 캠페인의 자격 조건(예: 기존 10% 할인 쿠폰 사용 완료)을 확인한다. 조건을 충족하는 회원에게만 `campaignId` 기준 고유 발급 키로 쿠폰 한 장을 만든다.

인증·쿠폰 발급·쿠폰 조회 중 하나라도 완료되면 해당 회원은 `campaignId`의 **전환 완료자**가 된다. 이 상태가 SMS 제외 목록의 근거가 된다.

### 3. CRM SMS 보완 발송

카카오 발송 후 48~72시간이 지난 뒤, 아래 조건을 모두 만족하는 CRM 회원에게만 SMS를 보낸다.

1. `status = active`이고 `marketingConsent = true`이다.
2. SOLAPI 수신거부·프로젝트 내부 발송 차단 목록에 없다.
3. 같은 `campaignId`로 쿠폰을 이미 받거나, 이벤트 링크를 통해 인증·수령 완료하지 않았다.
4. 최근 7일 이내 같은 성격의 프로모션 SMS가 없다.
5. 같은 `campaignId`로 SMS를 이미 전송하지 않았다.

SMS 링크에는 `utm_source=sms`, `utm_campaign={campaignId}`를 사용한다. 광고성 SMS는 `(광고)[NOPS]`, 문의처, 무료 수신거부 `080-500-4233`을 포함한다.

### 4. 종료 및 재발송 규칙

캠페인 종료 24시간 전에는 미전환자에게 최대 1회의 리마인드만 허용한다. 카카오와 SMS 모두 받은 고객에게 같은 캠페인의 세 번째 메시지는 보내지 않는다. SOLAPI 접수 실패는 자동 재시도 전 실패 코드·수신거부 여부·발신차단 여부를 확인한다.

## 발송 전 체크리스트

| 확인 항목 | 카카오 | SMS |
|---|---:|---:|

| 적격 대상·쿠폰 1회 발급 검증 | 링크 인증 단계 | 발송 대상 추출 단계 |
| 수신 동의·차단 제외 | 채널 친구 `I` 타게팅 | CRM 마케팅 동의·SOLAPI 차단 목록 |
| 문구·링크·UTM 검수 | 필수 | 필수 |
| 광고성 고지·080 | 브랜드 메시지 가이드 확인 | 필수 |
| 08:00~20:50 KST 예약 | 필수 | 필수 |
| 발송 수·예상 비용·발송 담당자 확인 | 필수 | 필수 |

## 최소 데이터 모델

운영을 자동화하려면 현재 단순 `alimtalk_logs` 외에 캠페인·발송·전환 이력을 보관해야 한다.

| 데이터 | 핵심 필드 | 용도 |
|---|---|---|
| `campaigns` | id, name, startsAt, endsAt, benefit, status | 하나의 캠페인 정의 |
| `campaign_messages` | campaignId, memberId(선택), channel, phone, status, solapiRequestId, sentAt | 카카오/SMS 채널별 발송 중복 방지 |
| `campaign_interactions` | campaignId, memberId, source, verifiedAt, couponId | 링크 유입·인증·수령 기록 |
| `campaign_coupon_grants` | campaignId, memberId, couponId, grantKey | 회원당 1회 쿠폰 보장 |

## 성과 측정

카카오 발송 수와 SMS 발송 수를 단순 합산하면 실제 도달 고객 수를 알 수 없다. 최종 성과는 인증된 CRM 회원을 기준으로 측정한다.

| 지표 | 산식 |
|---|---|
| 링크 유입 | UTM 소스별 이벤트 페이지 방문 수 |
| 인증 전환 | 인증 완료 회원 수 ÷ 링크 유입 수 |
| 쿠폰 수령 | 캠페인 쿠폰 발급 회원 수 ÷ 인증 완료 회원 수 |
| 쿠폰 사용 | 사용 완료 쿠폰 수 ÷ 캠페인 쿠폰 발급 수 |
| SMS 보완 효율 | SMS 발송 뒤 신규 인증·수령한 회원 수 |
| 채널 중복 노출 | 같은 `campaignId`에서 카카오 유입 후 SMS도 수신한 회원 수 |

## 알려진 한계

카카오 채널 친구 상태를 CRM이 직접 조회하지 않는 한, 카카오 메시지의 실제 수신자와 CRM SMS 수신자의 완전한 교집합 제거는 불가능하다. 이 설계는 링크 인증 후 전환한 회원을 SMS 대상에서 제외해 **혜택 중복과 후속 메시지 중복**을 막는 방식이다. 채널 친구에게 보낸 첫 메시지와 CRM SMS가 모두 도달하는 가능성은 남는다.
