## 처리 결과

기존 답변 대기 문의는 13건이었다. 조회 도구의 줄바꿈 표시 때문에 처음 15행으로 보였으나, 직접 DB 조회로 실제 13건임을 확인했다. 접수 순서로 사실관계와 기존 쿠폰·결제·적립 내역을 확인하고 13건 모두 회신했다. 동일 고객의 연락처 수정 관련 문의 2건은 메일 1통으로 합쳐 중복 회신을 막았다.

## 답변 완료 9건

쿠폰 발급 지연 문의는 현재의 발급일·유효기간·사용 처리 상태를 기준으로 안내했다. DB의 사용 처리 기록은 실제 고객 사용의 증명과 구분했으며, 본인이 사용하지 않았다면 추가 확인을 요청하도록 안내했다. 이메일 인증 문의에는 현재의 이메일 OTP 접속 방식을 안내했다.

운영자가 2026-10-16 00:40 KST에 **해피아워에도 가입 기념 10% 할인 쿠폰 추가 적용 가능**으로 승인했고, 해당 문의 답변에 반영했다. 이 결정은 다른 할인 쿠폰 간 중복 사용 허용이나 9월 이벤트 쿠폰 연장을 의미하지 않는다. 상세 기준은 `docs/happy-hour-coupon-policy.md`에 기록했다.

연락처 정정 요청은 문의와 회원의 이메일·회원 ID, 기존 전화번호 일치 및 새 번호의 다른 계정 중복 여부를 확인한 뒤 1명만 수정했다. 변경값은 DB 재조회로 검증했다. 쿠폰·적립금·수신동의는 그대로 유지했다.

## 구현·검증

관리자 회원 상세와 고객 마이페이지에 연락처·생년월일 수정, 저장, 취소 버튼을 추가했다. 고객은 이메일 OTP 인증 후 회원 ID·이메일에 결합된 수정 전용 토큰으로만 수정한다. 토큰은 30분 뒤 만료하며, URL의 회원번호나 위조·타인 토큰만으로는 새 수정 API를 실행할 수 없다. 전화번호 표준화·충돌 검사 및 실제 날짜 검증을 적용했고, 수정 자체로 쿠폰을 새로 발급하거나 수신동의를 변경하지 않는다.

관리자 문의에는 추가 확인 안내를 보내고 대기를 유지하는 기능을 추가했다. 답변 메일 API 오류를 성공으로 잘못 처리하지 않도록 보정했으며, 메일 발신 주소 환경변수의 리터럴 `\\u003c`·`\\u003e`를 `<`·`>`로 정규화했다. 고객 입력 및 답변은 HTML 이스케이프 처리하며, 신규 답변 로그에 고객 연락처·메일 주소를 출력하지 않는다.

TypeScript 검사, Vitest **21개 파일·72개 테스트**, 프로덕션 빌드를 통과했다. 390px 모바일 화면에서 고객·관리자 수정 및 URL 번호만으로는 수정에 진입할 수 없는 동작도 검증했다. UI 테스트는 응답을 격리한 화면 검증이며 실제 테스트 회원 가입·메일 발송·DB 수정은 하지 않았다. 기존 콜키지 테스트의 오후 반올림 오류는 운영 로직 변경 없이 날짜 경계 비교로 수정했다.

**회원정보 수정 기능의 실사이트 게시 완료는 아직 확인되지 않았다.** 저장된 새 체크포인트를 게시한 뒤 배포 버전을 확인해야 한다. 위 고객 회신과 실제 연락처 정정은 운영 DB·메일 API에서 실행되어 소스 코드 게시와 별개로 적용돼 있다.

## 잔여 운영 주의

새 회원정보 수정 API는 본인인증을 요구한다. 그러나 기존 레거시 회원정보·쿠폰 조회 등 전체 고객 API에 대한 인증 강화까지 이번 범위에서 완료했다고 주장하지 않는다. 기존 조회 및 다른 변경 API의 인증 구조는 별도 보안 검토 대상으로 남긴다. 기존 운영 TODO도 이번 작업과 무관한 항목을 완료로 바꾸지 않았다.
